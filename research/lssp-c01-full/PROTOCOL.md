## Analysis, declared before new outcomes

The whole workload window is the principal unit. All summaries are descriptive for this finite frozen corpus. No confidence intervals, p-values, FDR, population generalization, independent-request or independent-window assumptions. Repeated loads and capacities are paired conditions on the same windows. Related or overlapping windows remain visible; do not inflate sample size by pooling requests or conditions.

1. Export every metric from every planned cell, including counts, nulls, unfinished requests, resource/work counts and observation time. Keep all 5,760 rows, no silent exclusions. Conditional completed-request latency/TTFT/TPOT must always be read with their population counts and completion fraction. Means of window p95 values are **means of window p95 values**, never pooled-request p95.
2. Ranking endpoints (direction): ANWG, completion fraction, completed-output token throughput, emitted token throughput and request throughput (higher); mean and p95 latency, TTFT and TPOT (lower). Thus 11 endpoints. Export all six pairwise policy differences per window/region/KV/endpoint (A minus B, oriented difference, both values, missingness and practical margin). Every pairing uses identical window/input/configuration.
3. Rank all four policies with exact equality and average ranks. A null policy prevents a complete four-policy ranking: retain observed values but mark the ranking missing. Count exact top sets, ties and missing rankings separately, by source/region/KV/endpoint. An explicitly labeled sensitivity top set uses distance from the best <= 1e-12 * max(1, abs(best)); it does not replace exact ranks or practical-reversal decisions.
4. Compute source-specific equal-window means, min/max and observed/missing counts at fixed region/KV/policy/endpoint. Report exact top sets of source means only when all 40 windows contribute for every policy; otherwise mark incomplete. These are source differences at matched **region labels**, not equal absolute load factors across windows or sources. Export every factor. Do not attribute differences causally to source identity.
5. Primary practical reversal: for a policy pair and metric, orient improvement toward larger being better. A condition's relative advantage is abs(A-B)/abs(loser's value), where loser is selected using the metric direction. A zero loser or a missing value makes the condition unestimable; nonzero ties are estimable with zero margin. A reversal requires opposite oriented signs and **strictly greater than 10% at both endpoints**. Compare the represented binary metric values exactly as rational numbers against 1/10, without boundary tolerances. Retain numerator, eligible denominator, total comparisons and unestimable count. Tied comparisons stay in the eligible denominator. No alternative threshold is substituted.
6. Separate reversal tables: (a) within-source window stability at fixed region/KV/metric, all 780 unordered window pairs; (b) between-source differences at fixed region/KV/metric, all 1,600 cross-source window pairs, never pretend same-index windows are matched; (c) load effects within each window/KV/metric, all 15 region pairs; (d) KV effects within each window/region/metric; (e) metric-choice effects within each window/region/KV, all 55 endpoint pairs, each endpoint oriented separately. Each comparison includes all six policy pairs. Counts are dependent descriptive comparisons, not independent trials or Monte Carlo endpoints. Also report source-mean reversals for the three source pairs, conditional on complete window support.
7. Chronological sensitivity: use the frozen EARLY/MIDDLE/LATE labels (20/10/10 windows per source). Also form four consecutive blocks of ten after sorting within source by source-file hash, raw arrival-time minimum, start row, window ID. These blocks describe corpus ordering, not equal-duration time series or independently sampled blocks. Export block membership, source-file identity, raw time range and row-overlap diagnostics; report conditional rank frequencies and equal-window metrics by stratum and block.
8. Mean/tail, throughput, completion and goodput trade-offs are exposed by complete endpoint tables and metric-choice reversal counts. Keep negative, tied and inconclusive results. Do not select favorable regions, capacities or metrics after outcomes. Source, region, KV and metric effects remain separate tables, with explicit keys and denominators.

The original 36 historical supported reversal records remain contextual evidence in the inherited pilot materials. No new historical-reproduction/persistence claim is made: project-maintained adaptations are not identical historical policies, and the shared execution contract changes the estimand. This is a synthetic CPU discrete-event comparison, neither a native GPU benchmark nor a faithful historical-engine reproduction. Metric-layer deadlines use historical synthetic/oracle-derived construction, not deployable online deadline information.

Existing contract tests cover policy intentions, deterministic runs, future-input/latent-output noninterference and adversarial corruptions. New tests cover exact plan coverage, duplicate/foreign cells, identity-bound reuse, immutable restart, deadline stop and descriptive algebra, including independent brute-force reversal and rank oracles.

Before one submission: complete reuse audit; freeze and hash this protocol, input manifest, source and tests; pass local and pinned-Wulver tests and independent input reconstruction. One CPU, 4 GiB, no GPU, at most nine hours. No arrays, retries or follow-up submission. A persistent mkdir submission lock survives failure. A process lock and validated restart reject mismatches. Final cell directories are committed atomically, never overwritten; interrupted attempts remain preserved. Stop scheduling at eight hours, reserving one hour for finishing a cell and read-only validation/analysis. If time remains insufficient, save partial status and stop; no automatic extension.

After complete execution, reread every planned cell through the event referee, write deterministic descriptive tables, and independently recompute source means/ranks and reversal counts without calling the production summarizer. A completion marker requires exact coverage and successful independent report verification. Independent human result review is still required. Startup health is not scientific completion or calibration. After this final campaign, the next phase is independent result review, manuscript revision and submission, not another experiment.
