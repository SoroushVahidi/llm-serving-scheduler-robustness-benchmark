## PR #4: type compatibility and remaining boundaries

`Scheduler.get_kv_cache_usage -> KVCacheManager.usage -> BlockPool.get_usage` returns `1.0 - free/(total-1)` (Python float) or integer `0` when only the null block exists. The local CPU probe constructed real scheduler/block-pool objects: 1 block produced int 0; 9/17 blocks produced float 0.0; eight allocated usable blocks out of sixteen produced float 0.5. PR #4 accepted all four, with CUDA uninitialized. See [probe](check_runtime_boundary.py) and [log](evidence/runtime-boundary.log). **No repair or type weakening is justified for this pinned runtime.** Source denominator excludes null blocks; telemetry is occupancy, not total GPU-memory utilization.

NumPy scalars, tensors, booleans, strings, NaN, infinity and out-of-range values remain outside that boundary. If a future distributed collector changes representation, define a separately checked serialization boundary and pin it; do not coerce arbitrary objects with `float()` or default missing usage to zero. A finite fraction alone does not prove block conservation: also validate integer capacity/free/reserved counts and per-request ownership.

PR #4 rejects reused engine IDs before metadata mutation, including after completion; its registry intentionally lasts for the server execution. Future long-running campaigns need explicit epochs/server resets and stable lifetime identity, not deletion of entries to permit ambiguous reuse. Its invalid-KV check protects core batch/LST state; native output processing may already have progressed before it fails, so such a failure invalidates the run rather than authorizing retry from a partially updated state. The patch does not make runner ACKs, GPU tokens, prefix preservation, arbitrary cancellation races or distributed scalar telemetry fully verified.

Other boundaries found during this review are specification gaps, not changes to PR #4: new v2 counters must separate optimistic native progress from successful execution; sample-count rules must allow zero on partial prefills; stale replies after cancellation/preemption must be bound to an execution epoch; terminal requests must not acquire new LSTs. The proposed profile excludes asynchronous/pipeline overlap until those paths receive their own validated extension.
