## Minimal ordered work packages

1. **P0 — Approve and freeze the semantic target.** Select S01–S08 where relevant, metric boundaries and data mapping. Freeze versioned source/profile/deviation register and reviewed literal corpus before adapter implementation. Establish separate native and adapted-SLAI acceptance labels. CPU-only outcome: no ambiguous profile fields or oracle expectations.
2. **P1 — Implement the common ledger and independent validator first.** Pure CPU request/state/epoch/span/output conservation, ACK binding, allocation snapshots and invalid transition handling. Build independent table/enumeration reference without importing the production planner. Keep current v1 classes/launchers unmodified. Gate: all positive and corruption cases pass with no generated false success.
3. **P2 — Implement partial-prefill policy plans without general pressure.** Native profile first; then paused FIFO and approved SLAI ordering/LST on known-capacity fixtures. Feed accepted explicit work plans to the real native scheduler/runner boundary; do not let a generic simulator silently reschedule them. Gate: intended/native/reference tokens and transitions agree including starvation/overload observations; no unsupported behavior accepted.
4. **P3 — Add pressure/recompute only after the ledger is stable.** KV refusal taxonomy, rollback/refund, explicit victims, lifetime output preservation, cancel fencing and stale ACK handling. Gate: integer block and token conservation, finite measured feedback, no implicit retry; deterministic adversarial cases including self-preemption and permanently impossible requests. A source-compatible allocator alternative is a separate implementation, not a switch hidden in one result series.
5. **P4 — Prepare production-derived length replay and measurement hooks.** Raw coverage and approved target-token manifests, no timed tokenization, explicit failures/unknown metrics. Design instrumented vs uninstrumented comparisons before performance interpretation. Only after CPU gates may the author consider one separately bounded TP1 physical conformance allocation. This plan specifies no submission, GPU-hour grant or new workload distribution.
6. **P5 — Version the simulator independently.** Introduce a new simulator semantics ID; make it consume the approved token/KV/output state contract and compare state traces with native CPU objects. Preserve old classes/data for reproduction. Do not calibrate simulated durations using scheduler ranking outcomes or combine simulator repeats with physical repetitions.
7. **P6 — Extend TP2 then DP2 independently.** Add rank/replica evidence and failure corpus; model/head partitioning and router controls first. Each topology needs its own later physical gate. PP/multi-node/context parallelism are optional new contracts, not implicit TP/DP support.
8. **P7 — Authorize main-study preparation only after all required policy×deployment gates.** Confirm additional policy fidelity, common model/coverage, outcome-blind calibration, hardware controls, independent statistics and held-out splits. Do not launch the illustrative 3,456-run matrix from this document.

## Scope and scientific effect

The minimum credible next coding task is P1 after S01/S03/S05/S06 approval: a CPU-only ledger and independent conformance validator, with no GPU jobs and no change to the approved MGPU06 pair. Full long-prefill/KV behavior is not a small patch to PR #4. Native sample timing, binary class order, memory refusal and retained-prefix work can change policy decisions and service work; the direction or existence of a ranking reversal is unresolved. Stable/tied/inconclusive outcomes remain valid.

Resource estimates must follow future measured startup/runtime/pressure costs under an approved budget. Current 50-minute first-pair authorization is not reusable permission for these new profiles. This task consumed no GPU-hours and did not submit or probe Slurm.
