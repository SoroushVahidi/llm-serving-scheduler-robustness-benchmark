## Critical boundary decision

The proposed general path cannot be implemented by passing an arbitrary plan into pinned `Scheduler.schedule()`: there is no such API. Source-backed tests show substitution even without pressure. P2A therefore supplies an acceptance **verification** boundary for compatible native-FCFS plans, and records **NO-GO for arbitrary SLAI enforcement**. A future hook/fork must expose verifiable control before runner submission and account for native KV changes; it requires review before implementation. No fake native acceptance, sampler output, execution or physical acknowledgment fills this gap.
