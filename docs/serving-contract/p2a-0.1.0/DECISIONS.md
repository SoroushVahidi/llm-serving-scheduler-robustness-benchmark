# Prospective P2A scope and decision recommendations

This document records the author's explicit authorization to implement **CPU-only P2A** on PR #6. It preserves [P1 delegated approval](../p1-0.1.0/APPROVAL_AMENDMENT.md) and the original [v2 decision register](../v2.0.0-draft.1/AUTHOR_DECISIONS.md). Authorization to implement this narrow boundary is not acceptance of physical fidelity, a change to the frozen study protocol, or approval of an unresolved scheduler design.

## Next implementation gate

1. Author review of the source-backed **NO-GO for arbitrary native plan injection**. Select whether to pursue a narrowly instrumented native scheduler hook/fork that can constrain work before runner submission, or retain native-only verification. No such hook was implemented here.
2. Approve S02 candidate or specify an alternative. Freeze new semantic profile and literal distinguishing cases before policy implementation; never modify old MGPU manifests.
3. Review a runner-side execution attestation: actual batch/epoch/positions, sampled-row validity, abort state, completion/quiescence, and clock domain. Synthetic acknowledgments cannot satisfy it. Acknowledged counters must be checked against actual runner inputs/outputs.
4. Keep S04 general pressure and S07/S08 blocked until their evidence/choices are available. Approval of a CPU hook would not authorize GPU work or the MGPU06 first pair.

Stable native FCFS ordering in these CPU fixtures is not evidence for scheduler ranking portability. The adapter and diagnostic copies are not approved for timed physical measurements.
