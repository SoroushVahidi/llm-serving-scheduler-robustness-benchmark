# Control, rejection and execution attestation

The API is opt-in: `ControlledBoundary(native_scheduler, run_id, enabled=True)`. The scheduler must be an empty exact native CPU Scheduler satisfying every unchanged P2A configuration/source guard. One caller owns it, one nonempty batch at a time. No concurrent mutation, prefix cache, speculative decoding, multimodal/encoder/LoRA work, connectors, async, pressure/preemption/recomputation or distributed mode is supported. No GPU runner is created.

`ControlPlan(Proposal(batch_id, spans, token_budget, active_limit), holds)` uses P2A's immutable half-open request/epoch/start/end spans. Holds explicitly enumerate **every resident request not selected**, including paused prefills. Waiting requests omitted from selection remain waiting. Held residents retain blocks and slots. Budget is the sum of selected input positions; slots are all prior residents plus newly admitted requests, including holds. Actual configured bounds must match the proposal.

Read-only preflight checks identity, P1/native progress, epoch zero, exact start, known frontier, model context, native status/inflight/preemption/queue consistency, pool conservation, lifetime no-pressure domain, token/slot bounds, explicit holds, and resident-before-waiting representability. A failure records refusal and stops the instance without queue/current-step/KV/progress mutation. P2A's own validation still runs afterward and is unchanged.

After preflight the hook explicitly orders selected residents and waiting requests ahead of deferred entries. It skips unselected residents, stops before unselected waiting entries, and constrains each selected allocation's input count to the requested span (never raises a native upper bound). Native refusal raises before victim selection. Native wire output must equal the ordered proposal exactly; P2A independently rechecks it. On success canonical resident/remaining-waiting ordering is restored; selected counts/positions remain the actual native result. Canonical ordering restoration is not rollback of native scheduling or allocation.

**Failure semantics:** a later refusal may occur after an earlier request was allocated. This is a stopped, partially mutated native object, not an atomic transaction. No runner submission, P1 acknowledged progress, automatic retry, victim selection or recovery follows. Preserved failure snapshots report what changed. A stopped hook cannot be reused. The instance-local patch is not a security boundary against hostile in-process mutation; fault injection tests demonstrate detected violations, not arbitrary-code isolation.

`S02Boundary.schedule_s02(batch_id, stamp=...)` is the integrated partial profile. It validates class and lifetime-unique ordinal metadata at enqueue; only its planner can provide its plans. It updates paused FIFO only after successful boundary acknowledgment. `PrefillPolicy` is separately reusable with immutable request views; neither policy inputs nor its priority key contains an output limit or remaining-output oracle. The maximum output cap remains an engine safety bound. The S02 ID must not label arbitrary external plans.

## Execution-side attestation / 0.1.0

`ExecutionAttestation` is external evidence, not generated by the planner:

| Field | Required meaning |
|---|---|
| batch_id, native_step | Same accepted batch and scheduler iteration; no reuse or late binding |
| accepted | Canonically ordered `(engine request ID, epoch, start, end)` bindings actually accepted by scheduler |
| executed | Actual execution-side token positions, normalized to accepted request order; must equal accepted for complete success |
| sample_mask | Valid sampled-token eligibility per canonical request; intermediate prefill false, final prefill/decode true |
| completion | Complete / partial / failed; P2B accepts complete only and explicitly stops on others |
| quiescent, quiescence_evidence | Execution-side drain claim with unique evidence identity. P2B only checks a nonempty unique synthetic ID; a real bridge must retain and verify the referenced executor/device drain record |
| start, end | Typed ClockStamp, domain/category and causal bounds; fixture values are synthetic host-control values |
| provenance | `synthetic_cpu` only in this implementation; physical declarations rejected |

Actual native `ModelRunnerOutput` accompanies the attestation. Its request rows may be permuted by the V2 runner; a bijective ID/index map binds samples to requests. Canonical execution span order cannot be silently permuted, but valid physical row layout is not mistaken for policy order or chronological GPU execution order. Future instrumentation must capture actual runner input positions and valid sample counts, completion/abort/failure and drain boundaries. A host future or optimistic `num_computed_tokens` alone is insufficient. Actual GPU time/first-token emission remains NOT VERIFIED.

Attested clocks must be finite, within one domain, after planning and before host application. No synthetic span, sample mask or quiescence ID is physical evidence. No TTFT, TPOT, ITL, numerical correctness, overhead or LST measurement follows from these CPU fixtures.

## Independent validation

`p2b.reference.validate(journal, intents, require_complete=True)` reconstructs request-local state through the independent P1 referee and checks batch conservation itself. It imports no production adapter, policy, hook, native vLLM or torch. Its P2A-independent-reference provenance is documented; unchanged non-policy invariant checks are reused by source, not the adapter's acceptance decisions.

For `lssp-native-span-control/0.1.0`, an external intent map is mandatory. Tests write literal intent **before** calling the adapter; the referee never takes recorded native acceptance as its expected plan. For S02 it independently constructs a stream of token-position tickets from paused FIFO and immutable admission keys; budget prefixes determine expected spans. It reconstructs FIFO from acknowledged progress and compares the producer's advertised FIFO. Faulty priority, substituted chunks/requests/order, corrupted wire/ACKs, shared KV and missing execution all fail.

The verifier distinguishes a valid open prefix from a completed CPU run; transport closure is separate and remains false without actual emission/observation events. Physical status always remains NOT VERIFIED. The in-memory journals, deep copies, source compilation/hash checks and snapshots are diagnostic overhead; no timed-serving suitability is asserted.
